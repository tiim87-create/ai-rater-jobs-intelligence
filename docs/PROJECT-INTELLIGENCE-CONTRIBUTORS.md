# Project Intelligence Contributors — proposed design

Date: 2026-11-27. Extend Contributor Intelligence with structured first-hand project experience. Preserve broad catalog coverage for future expansion; distinguish core, extended, domain-specific and unverified market segments. This is a proposed design, not deployed.

## Entry points
Each vacancy should distinguish 'Suggest a vacancy correction' from 'Share your project experience'. The latter pre-fills vendor, stable listing ID, source URL, title and inferred project family, with contributor confirmation. Provide a standalone entry for former workers and expired/unlisted vacancies. Do not equate vacancy identity with project identity; link many listings to a stable project record after editorial review.

## Submission template
Vendor, public job title, project name if shareable, country/locale, approximate experience period, current/former role, application and qualification stages, typical task categories (non-confidential summaries), work platform if publicly shareable, workload and pay (optional; route to existing intelligence forms), quality feedback, practical experience, optional public evidence, preferred attribution or anonymity. Do not request credentials, personal identifiers, confidential client materials, live exam questions or proprietary task content.

## Editorial workflow
Submission -> review -> clarify if needed -> map to existing project or create candidate -> corroborate -> publish structured project overview with provenance and confidence. Distinguish first-hand testimony from independently verified facts. No automatic publication. Obtain explicit permission for publication and attribution. Keep contact details private.

## Implementation
Audit existing WordPress contribution entry points before modifying them. Reuse Contributor Intelligence infrastructure and existing pay/NTA forms. Add contextual CTA and project-specific form, moderation queue and project registry linkage. No changes to production in this design commit.
